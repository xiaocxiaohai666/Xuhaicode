# 票务预约系统 - 需求文档

## 1. 项目概述

### 1.1 项目名称
票务预约系统（Ticket Reservation System）

### 1.2 项目背景
本系统是一个基于C++开发的网络票务预约管理系统，采用客户端-服务器（C/S）架构，为用户提供在线注册、登录、浏览票务、预约订票、查看个人预约记录及取消预约等功能。

### 1.3 技术栈
| 分类 | 技术选型 | 说明 |
|------|---------|------|
| 编程语言 | C++ | 系统核心开发语言 |
| 网络通信 | TCP Sockets + Epoll | 高并发网络I/O处理 |
| 多线程 | pthread 线程池 | 并发处理客户端请求 |
| 数据序列化 | JSON (jsoncpp) | 客户端与服务端数据交互格式 |
| 数据库 | MySQL | 数据持久化存储 |
| 构建工具 | Makefile | 项目编译构建 |

## 2. 功能性需求

### 2.1 用户管理模块

#### 2.1.1 用户注册（ZC）
- **需求描述**：新用户可以通过手机号码注册账号
- **输入参数**：
  - `user_tel`：用户手机号码（作为唯一标识）
  - `user_name`：用户姓名
  - `user_passwd`：用户密码
- **处理逻辑**：
  1. 客户端发送JSON格式的注册请求
  2. 服务端接收请求并解析JSON数据
  3. 连接MySQL数据库，将用户信息写入`user_info`表
  4. 返回注册成功/失败的响应
- **响应格式**：`{"status": "OK/ERR"}`
- **前置条件**：用户未登录状态

#### 2.1.2 用户登录（DL）
- **需求描述**：已注册用户可通过手机号码和密码登录系统
- **输入参数**：
  - `user_tel`：用户手机号码
  - `user_passwd`：用户密码
- **处理逻辑**：
  1. 客户端发送登录请求
  2. 服务端验证手机号与密码是否匹配
  3. 验证通过返回用户名，标记登录状态
  4. 验证失败返回错误提示
- **响应格式**：成功时 `{"status": "OK", "user_name": "xxx"}`，失败时 `{"status": "ERR"}`
- **前置条件**：用户未登录状态

### 2.2 票务管理模块

#### 2.2.1 查看可预约票务（CKYY）
- **需求描述**：用户可以查看当前所有可预约的票务信息
- **输入参数**：无（登录用户直接查看）
- **处理逻辑**：
  1. 查询`ticket_table`表中状态为可用（status=1）的票务记录
  2. 返回票务ID、名称、总票数、已预订数、时间等信息
- **响应格式**：
  ```json
  {
    "status": "OK",
    "num": 2,
    "ticket_arr": [
      {
        "ticket_id": 1,
        "ticket_name": "演唱会A",
        "ticket_max": 100,
        "ticket_count": 50,
        "day_time": "2026-08-20 19:00:00"
      }
    ]
  }
  ```
- **前置条件**：用户已登录

#### 2.2.2 预约票务（YD）
- **需求描述**：登录用户可以预约指定的票务
- **输入参数**：
  - `user_tel`：用户手机号码
  - `ticket_id`：票务ID
- **处理逻辑**：
  1. 检查该票务的已预订数量是否达到上限
  2. 若未达上限，开启数据库事务
  3. 更新`ticket_table`表的已预订数（count+1）
  4. 在`yd_table`表中插入预约记录
  5. 提交事务，返回成功
  6. 若已达上限，返回预约失败
- **并发控制**：使用MySQL事务保证数据一致性
- **响应格式**：`{"status": "OK/ERR"}`
- **前置条件**：用户已登录，且该票务尚有剩余

#### 2.2.3 查看我的预约（YDXX）
- **需求描述**：登录用户可以查看自己的所有预约记录
- **输入参数**：
  - `user_tel`：用户手机号码
- **处理逻辑**：
  1. 联表查询`yd_table`和`ticket_table`，获取当前用户的所有预约信息
  2. 返回预约ID、票务名称、总票数、已预订数、预约时间等
- **响应格式**：
  ```json
  {
    "status": "OK",
    "num": 1,
    "my_ticket_arr": [
      {
        "yd_id": 1,
        "ticket_name": "演唱会A",
        "ticket_max": 100,
        "ticket_count": 50,
        "day_time": "2026-08-20 19:00:00"
      }
    ]
  }
  ```
- **前置条件**：用户已登录

#### 2.2.4 取消预约（QXYD）
- **需求描述**：登录用户可以取消自己的预约
- **输入参数**：
  - `user_tel`：用户手机号码
  - `yd_id`：预约ID
- **处理逻辑**：
  1. 验证预约记录是否存在且属于当前用户
  2. 开启数据库事务
  3. 从`yd_table`表删除预约记录
  4. 回滚`ticket_table`表的已预订数（count-1）
  5. 重置自增ID
  6. 提交事务，返回成功
- **响应格式**：`{"status": "OK/ERR"}`
- **前置条件**：用户已登录，且该预约记录存在

## 3. 数据库设计

### 3.1 数据库信息
- **数据库名称**：`c2411db`
- **数据库类型**：MySQL

### 3.2 数据表设计

#### 3.2.1 用户信息表（user_info）
| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | AUTO_INCREMENT PRIMARY KEY | 主键，自增 |
| Tel | VARCHAR(20) | UNIQUE NOT NULL | 用户手机号，唯一标识 |
| Name | VARCHAR(50) | NOT NULL | 用户姓名 |
| Passwd | VARCHAR(50) | NOT NULL | 用户密码 |
| Status | TINYINT | DEFAULT 1 | 账号状态（1：正常） |
| RegDate | DATE | | 注册日期 |

**建表SQL示例**：
```sql
CREATE TABLE user_info (
  id INT AUTO_INCREMENT PRIMARY KEY,
  Tel VARCHAR(20) UNIQUE NOT NULL,
  Name VARCHAR(50) NOT NULL,
  Passwd VARCHAR(50) NOT NULL,
  Status TINYINT DEFAULT 1,
  RegDate DATE
);
```

#### 3.2.2 票务信息表（ticket_table）
| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| Tk_id | INT | AUTO_INCREMENT PRIMARY KEY | 票ID，自增 |
| Tk_name | VARCHAR(100) | NOT NULL | 票务名称 |
| Tk_max | INT | NOT NULL | 最大可预约数量 |
| Count | INT | DEFAULT 0 | 已预约数量 |
| DateTime | DATETIME | | 演出/活动时间 |
| Status | TINYINT | DEFAULT 1 | 状态（1：可预约） |

**建表SQL示例**：
```sql
CREATE TABLE ticket_table (
  Tk_id INT AUTO_INCREMENT PRIMARY KEY,
  Tk_name VARCHAR(100) NOT NULL,
  Tk_max INT NOT NULL,
  Count INT DEFAULT 0,
  DateTime DATETIME,
  Status TINYINT DEFAULT 1
);
```

#### 3.2.3 预约记录表（yd_table）
| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| yd_id | INT | AUTO_INCREMENT PRIMARY KEY | 预约ID，自增 |
| user_tel | VARCHAR(20) | FOREIGN KEY | 用户手机号，外键关联user_info |
| tk_id | INT | FOREIGN KEY | 票ID，外键关联ticket_table |
| Yd_time | DATETIME | DEFAULT NOW() | 预约时间 |

**建表SQL示例**：
```sql
CREATE TABLE yd_table (
  yd_id INT AUTO_INCREMENT PRIMARY KEY,
  user_tel VARCHAR(20),
  tk_id INT,
  Yd_time DATETIME DEFAULT NOW()
);
```

## 4. 非功能性需求

### 4.1 性能需求
| 需求项 | 指标 | 说明 |
|--------|------|------|
| 并发连接数 | ≥ 100 | 系统应支持至少100个客户端同时连接 |
| 响应时间 | ≤ 500ms | 常规操作响应时间不超过500毫秒 |
| 吞吐量 | ≥ 50 QPS | 每秒处理请求数量 |
| 线程池大小 | 可配置 | 默认4个工作线程 |
| 任务队列容量 | 1024 | 最大待处理任务数 |

### 4.2 可靠性需求
| 需求项 | 说明 |
|--------|------|
| 事务一致性 | 预约/取消操作必须使用数据库事务保证数据一致性 |
| 异常处理 | 服务端必须处理客户端异常断开、数据库连接失败等异常情况 |
| 资源释放 | 客户端断开连接时必须正确释放相关资源（关闭套接字、销毁对象） |
| 配置容错 | 配置文件读取失败时使用默认值启动 |

### 4.3 安全性需求
| 需求项 | 说明 |
|--------|------|
| 用户认证 | 所有票务操作需在登录状态下进行 |
| 数据隔离 | 用户只能查看和操作自己的预约记录 |
| SQL注入防护 | 应对用户输入进行合理校验（当前版本为学习用途，生产环境需加强） |
| 密码存储 | 当前为明文存储（生产环境应加密存储） |

### 4.4 可扩展性需求
| 需求项 | 说明 |
|--------|------|
| 模块化设计 | 采用Socket基类+派生类的设计模式，便于扩展新的连接类型 |
| 操作类型扩展 | OP_TYPE枚举便于扩展新的业务操作 |
| 配置灵活 | 服务器IP、端口、监听队列大小均可通过配置文件指定 |

### 5.3 通信协议

#### 5.3.1 请求消息格式
所有请求均使用JSON格式，通过TCP套接字传输：

**通用请求格式**：
```json
{
  "type": 操作类型,
  ...业务参数
}
```

**操作类型枚举（OP_TYPE）**：
| 枚举值 | 数值 | 说明 | 业务参数 |
|--------|------|------|----------|
| ERR | 0 | 错误 | - |
| DL | 1 | 登录 | user_tel, user_passwd |
| ZC | 2 | 注册 | user_tel, user_name, user_passwd |
| CKYY | 3 | 查看可预约 | - |
| YD | 4 | 预约票务 | user_tel, ticket_id |
| YDXX | 5 | 查看我的预约 | user_tel |
| QXYD | 6 | 取消预约 | user_tel, yd_id |
| TC | 7 | 退出 | - |

#### 5.3.2 响应消息格式

**通用响应格式**：
```json
{
  "status": "OK" 或 "ERR",
  ...业务数据
}
```

**各操作响应详情**：
| 操作 | 成功响应 | 失败响应 |
|------|---------|---------|
| ZC(注册) | `{"status": "OK"}` | `{"status": "ERR"}` |
| DL(登录) | `{"status": "OK", "user_name": "xxx"}` | `{"status": "ERR"}` |
| CKYY(查看) | `{"status": "OK", "num": N, "ticket_arr": [...]}` | `{"status": "ERR"}` |
| YD(预约) | `{"status": "OK"}` | `{"status": "ERR"}` |
| YDXX(我的) | `{"status": "OK", "num": N, "my_ticket_arr": [...]}` | `{"status": "ERR"}` |
| QXYD(取消) | `{"status": "OK"}` | `{"status": "ERR"}` |
